# Operational Resilience Security Model

## Security architecture that survives contact with reality

The **Operational Resilience Security Model (ORSM)** is an architectural
assurance framework for evaluating whether security controls continue to
provide effective protection without creating disproportionate
operational risk.

ORSM complements established approaches such as NIST CSF 2.0, ISO/IEC
27001, NCSC Secure by Design, SABSA and Zero Trust. It does not seek to
replace them. It adds an operational assurance lens: whether the
resulting security architecture remains proportionate, sustainable,
recoverable and resilient once deployed.

> **Does this control improve security outcomes without creating
> disproportionate operational risk?**

ORSM evaluates architecture across seven operational assessment domains:

1.  Protection Intent
2.  Complexity Management
3.  Operational Sustainability
4.  Operational Resilience
5.  Recovery Engineering
6.  Human Factors
7.  Dependency Resilience

## The ORSM commitment

-   Every control should exist for a clear purpose.
-   Every architectural decision should be proportionate.
-   Complexity should be understood and actively managed.
-   Recovery should be designed rather than assumed.
-   Dependencies should be recognised before they become
    vulnerabilities.
-   People should be considered an integral part of secure design.

> **Security is not measured by the controls we deploy. It is measured
> by the architecture we can continue to operate.**

**Operational security is proven through survivability.**
